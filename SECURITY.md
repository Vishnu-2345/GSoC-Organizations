# Security Policy

## Supported versions

Security updates are applied to the current `main` branch and the production
deployment at [gsocorganizations.xyz](https://gsocorganizations.xyz). Older
commits, forks, and unofficial deployments are not supported.

| Version                | Supported |
| ---------------------- | --------- |
| Current `main` branch  | Yes       |
| Production deployment  | Yes       |
| Older commits or forks | No        |

## Reporting a vulnerability

Please do not report security vulnerabilities in a public issue, discussion,
pull request, or social media post.

Report a vulnerability privately through [GitHub's security advisory
form](https://github.com/rohanmalhotracodes/GSoC-Organizations/security/advisories/new).
Include, when possible:

- A clear description of the vulnerability and its impact
- The affected page, file, workflow, or dependency
- Steps or a minimal proof of concept that reproduces the issue
- Any suggested mitigation or fix
- Whether the vulnerability has been disclosed elsewhere

Reports concerning the website, source code, dependencies, GitHub Actions,
deployment configuration, or accidental exposure of sensitive information are
all welcome.

## What to expect

- The maintainer will acknowledge a report as soon as reasonably possible.
- The report will be investigated privately and may require follow-up questions.
- A fix and disclosure timeline will be coordinated according to severity and
  available maintainer capacity.
- Please keep the vulnerability confidential until the maintainer confirms that
  it is safe to disclose.
- Good-faith reporters will be credited in the advisory unless they prefer to
  remain anonymous.

## Safe-harbor expectations

We welcome good-faith security research that avoids privacy violations, data
destruction, service disruption, social engineering, and access beyond what is
necessary to demonstrate the issue. Do not test against other users' data or
accounts. Stop testing and report the issue if you encounter sensitive data.
